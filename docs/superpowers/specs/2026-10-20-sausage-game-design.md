# 香腸體感投擲遊戲：第一版設計

## 目標與範圍

手機作為體感控制器，電腦以 Pygame 呈現從玩家眼前的鍋子，往遠方桌面投擲一根香腸。採 2.5D 透視；第一版固定正前方與仰角，只由揮動強弱控制射程。成功時整根香腸落在桌面並平躺停住，可重新準備再玩。

保留現有 SA.py（包含使用者未提交的修改）、DAI.py、DAN.py、csmapi.py、Agent.py 與原 README。遊戲、美術及說明以新增檔案提供，不需要未載入的課程附件。不含左右瞄準、完整 3D、多玩家或排行榜。

## 模組與啟動

- game.py：遊戲入口、Pygame 繪圖、操作與主迴圈。單獨啟動即可鍵盤試玩。
- game_core.py：不依賴 Pygame 的拋體、桌面碰撞與揮動狀態邏輯，供單元測試。
- SA_game.py：獨立 IoTtalk 設定與 Dummy_Control 回呼。沿用目前裝置模型、伺服器與 ODF 名稱；使用獨立裝置名稱及 ID，避免與原裝置混淆，不送隨機感測資料。
- game_input.py：只使用標準函式庫的本機 UDP 傳輸與資料驗證，接收端僅綁定 127.0.0.1，可設定連接埠。
- requirements-game.txt、GAME_README.md、tests/test_game_core.py：遊戲額外依賴、繁體中文操作說明與核心測試。

手機模式開兩個程序：python game.py 與 python DAI.py SA_game。使用者需在 IoTtalk 網頁把手機感測來源連至新遊戲裝置的 Dummy_Control；原本裝置的連線不會自動複製。鍵盤模式只開 game.py，無須連線或匯入 DAI。

## 資料流與錯誤處理

Dummy_Control 接受現有 [[x,y,z]] 包裝，也支援直接 [x,y,z]。只接受三個有限數值，拒絕布林值、NaN、無限大與錯誤形狀。接收後以小型 JSON 封包傳送本機遊戲程序，不在 IoTtalk 執行緒操作 Pygame。

遊戲每幀非阻塞讀取資料，限制每幀處理量並淘汰積壓的舊資料，避免卡住畫面。尚未啟動遊戲時，感測回呼仍可繼續執行。封包無效時忽略；連接埠衝突顯示可理解的錯誤與更換方式。手機資料超過一秒未更新時顯示未連線；校正或等待揮動時資料中斷則取消準備，避免恢復連線後意外投擲。

## 操作與力道

提供畫面上的「準備」按鈕與 R 快捷鍵。準備後先保持手機靜止約一秒，至少收集五筆新樣本，以三軸合成強度的中位數估計靜止基準；樣本不足或晃動過大則提示重新校正。

校正完成後等待揮動。動作強度為 max(0, sqrt(x²+y²+z²) - baseline)。超過可設定門檻後，收集約 250 毫秒的峰值，再映射成有上下限的初速。門檻與力道倍率集中設定並寫入說明，實際手機單位不同時可調整；不宣稱已完成真機調校。連續揮動每次準備只投一次；等待十秒未揮動則返回待機。

鍵盤模式可按住空白鍵蓄力、放開投擲；蓄力條顯示力道。飛行與結果狀態不再接受新的投擲。結果畫面可按 R 重玩，Esc 或關閉視窗退出。手機與鍵盤共用相同的初速與物理模型。

## 物理與碰撞

世界座標 x 為左右、z 為前後、y 為高度。香腸以固定角度向 +z 拋出，受固定重力影響；用經過時間計算位置，使射程不依賴畫面更新率。模型內明確設定鍋子起始位置、桌面高度與矩形範圍，以及香腸長度和半徑。

第一版香腸固定沿 x 橫放，不做旋轉碰撞。模型以香腸底部高度判定接觸桌面；下降穿越桌面高度時求精確交點，不能只檢查當幀位置，以免大時間步跳過桌面。

只有整根香腸的平面外框都在桌面內才成功，包括邊界。成功後把香腸固定在接觸位置；只部分碰到桌邊則判失敗，第一版不模擬桌邊彈跳。未落在桌上時繼續下降到地面，依落點顯示「力道不足」「飛過桌子」或「碰到桌邊」。

## 畫面

以程式繪圖完成鍋子、香腸、桌子與背景，無額外圖片下載。透視投影使遠方物件變小，桌面呈梯形；高度另行影響投影位置。香腸有地面或桌面陰影，讓飛行高度與前後距離容易辨識。按照深度繪製桌子與香腸，避免桌前飛行被錯誤遮住。

介面呈現目前階段、準備操作、連線狀態、力道與結果。優先尋找系統中文字型，缺字型時使用英文備援文字，確保提示仍可閱讀。

## 驗收與驗證

自動測試涵蓋：低／適中／過強初速的不同結果、桌面邊界、中心在桌上但香腸超出邊界、大時間步仍正確碰撞；校正樣本不足、靜止不觸發、單次揮動只投一次、準備逾時與中斷；兩種感測包裝及無效資料。

使用 SDL dummy 視訊模式進行有限幀啟動與退出測試，並以本機封包驗證感測接收，不連遠端課堂服務。人工驗收確認透視、遮擋、鍵盤蓄力與成功平躺。手機實機揮動與 IoTtalk 網頁接線需具備手機及使用者的專案環境才可驗證，完成報告需區分已測與未測。
